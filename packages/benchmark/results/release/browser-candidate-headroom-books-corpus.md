## Source Contract

- Parser input: Prepared full rows use StreamReaderSync over a synchronous Iterable<Uint8Array[]> generated by byteBatches(fixture); live fetch rows consume Response.body either through EventReader or manually grouped AsyncIterable<Uint8Array[]> batches.
- Batch backpressure: byteBatches(fixture) yields one grouped batch per synchronous parser pull. fetchAsyncByteBatchFull groups Response.body with reader.read() only while filling the next yielded Uint8Array[] batch, so it is demand-driven and does not eagerly drain the stream.
- Fetch ReadableStream: fetchReadableStreamFull consumes fetch Response.body directly with EventReader while the local server repeats corpus bytes to the target size; fetchAsyncByteBatchFull manually groups Response.body reads into AsyncIterable<Uint8Array[]> batches under the same contract.
- Corpus/generated scope: Most corpus rows still load fetch(...).arrayBuffer() as a seed and replay it; fetchReadableStreamFull and fetchAsyncByteBatchFull are live browser streaming source rows.
