## 🔧 Architecture Quick Reference

### Event Flow

```
XML Input
  ↓
StaxXmlParser (async iterator of events)
  ↓
State Machine processEventAsync()
  ├─ START_ELEMENT → onSchemaActivatedSync()
  │   ├─ Register child schemas
  │   ├─ Extract immediate attributes
  │   └─ Create collectors
  ├─ CHARACTERS → onSchemaCollectText()
  │   └─ Add text to collectors
  └─ END_ELEMENT → onSchemaDeactivatedSync()
      ├─ Build result from collector
      ├─ Apply transforms (⚠️ MISSING!)
      └─ Add to parent collector
```

### Key Methods

- `matchesInContext()` - XPath matching with context resolution
- `onSchemaActivatedSync()` - Schema activation + immediate attribute extraction
- `onSchemaDeactivatedSync()` - Build results from collectors
- `extractObjectFromCollector()` - Extract object (⚠️ needs transform support)
- `unwrapSchema()` - Handle Transform/Optional wrappers

## 🎓 Key Learnings

### What Worked Well
- State Machine architecture is solid and extensible
- Context-based XPath matching handles complex patterns
- Immediate attribute extraction is the right approach
- Comprehensive documentation helps continuity

### What Needs Improvement
- Transform application was overlooked initially
- Memory management needs attention for large files
- Complex nested structures need more test coverage

### Design Decisions
- **All parsing through State Machine**: No hybrid approaches
- **Unwrap transparently**: Wrappers should be invisible to State Machine
- **Immediate extraction for attributes**: Can't wait for normal activation
- **Context-based matching**: Relative XPaths resolve using parent context
